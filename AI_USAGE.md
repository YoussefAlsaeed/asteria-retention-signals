# AI usage

How an AI coding agent was directed, challenged, and verified on this assessment. This is a running log, updated as work progresses. It contains no secrets and no full transcripts.

## Tools and models

| Tool | Model | Used for |
|---|---|---|

## Operating loop

1. **Human sets the task and scope.** Each session starts with a bounded request (for example "analyse the software-emphasis track", "initialise the repository").
2. **Agent proposes, human decides.** Architecture, metric definitions, scope cuts, and naming are presented as options with a recommendation; the human chooses.
3. **Agent executes in small, checkable steps.** Every step ends with evidence: a test run, a checksum, a lint result, or a diff to review.
4. **Human validates before it counts.** Nothing generated (citations, dataset codes, statistics, schemas) is treated as fact until checked against a primary source or the data itself.

## Session log

### 1. Brief analysis

- **Task:** explain the assessment, with focus on the software-emphasis track.
- **Agent output:** stage-by-stage breakdown, a proposed architecture (ports-and-adapters Python package, DuckDB for SQL, FastAPI service with a separate HTML dashboard, Playwright and axe for UI and accessibility tests), and a candidate list of planted data defects.
- **How the defect list was produced:** the starter data is generated by JavaScript embedded in the brief HTML. The agent read that generator and listed the injected defects (duplicates, `EL`/`ROM` country codes, blank countries, terminations before hire, blank termination types, `Sr Mgmt` level, blank hire dates, unknown regretted flags).
- **Validation status:** not yet validated. These are *expectations*. They will be confirmed or corrected by profiling the actual CSVs; any disagreement will be recorded here.
- **Notable judgement:** `EL` was classified as a canonical alias for Greece (it is Eurostat's own code), not as an error. This was presented to the human as a mapping rule rather than a quarantine rule.

### 2. Repository structure: suggestion materially changed

- **Agent suggestion:** a custom layout (`src/asteria/...`, `config/`, `dashboard/`, `tests/`).
- **Human challenge:** the brief already suggests a repository shape (`README · docs/ · src/ · tests/ · data/raw-or-fixtures/ · data/curated/ · dashboard/ · presentation/ · AI_USAGE.md`).
- **Outcome:** the agent's layout was reworked to use the brief's top-level names exactly, with the domain and adapter boundaries moved inside `src/asteria/`. `config/` and `pyproject.toml` were kept as justified additions. Reviewers should recognise the layout at a glance.

### 3. Repository initialisation: a silent integrity bug caught

- **Task:** create a private GitHub repository under the human's personal account.
- **Human decisions:** name `asteria-retention-signals`, owner `YoussefAlsaeed`, private visibility.
- **Problem found during staging:** Git on Windows warned that it would convert line endings on data files. That would have changed the bytes of the starter CSVs and invalidated the SHA-256 checksums in `assessment_data_manifest.json`, silently breaking the provenance chain.
- **Fix:** `.gitattributes` marks `*.csv`, `*.json`, and `data/**` as binary-exact (`-text`).
- **Verification:** SHA-256 of all three CSVs, both on disk and in the committed git blobs, matched the manifest. This check is now automated in `tests/test_starter_data.py`, so any future corruption fails the test suite.

### 4. Scaffolding

- **Agent output:** `pyproject.toml` (uv, hatchling, ruff, mypy strict, pytest), package stubs with one-line boundary docstrings, a Typer CLI entry point, a smoke test, and the manifest-integrity test.
- **Deviation from plan:** moving the starter files failed because another program held a file lock. The agent copied them instead, re-verified the checksums, and untracked the old folder rather than forcing deletion.
- **Verification:** `uv sync` succeeded; `uv run pytest` passed 4/4; `uv run ruff check .` was clean.

## Verification practices

- **Checksums** for every supplied artifact, enforced by a test.
- **Profiling before trusting** any agent claim about the data (pending).
- **Primary-source checks** for every external dataset code, licence, and publication lag before it enters the source register (pending).
- **Tests before claims:** a finding is only reported once it is reproducible from `uv run` commands.

## Failures and manual corrections

- Line-ending normalisation would have corrupted the evidence files (caught and fixed before the first commit).
- File lock prevented a move; copy plus checksum re-verification was used instead.

- External indicator choices, dataset codes, and publication lags are **not yet verified** against the live provider APIs.
- Metric definitions (six-month boundary, senior levels, headcount convention) are **not yet decided**. They depend on the clarification round.

## Appendix: domain glossary

The agent produced this glossary so a non-HR engineer could follow the business language of the brief. The human reviewed it for clarity. It also serves as the shared vocabulary for code, tests, and docs in this repository.

| Term | Plain meaning | Example |
|---|---|---|
| **Retention** | Keeping employees; the opposite of people leaving | "90% retention": 90 out of 100 people stayed |
| **Turnover** | People leaving; the opposite of retention | "10% turnover": 10 out of 100 left |
| **Voluntary exit** | The employee chose to quit | Found a better job |
| **Involuntary exit** | The company let them go | Dismissal or layoff |
| **End of contract** | A temporary contract simply ended | A one-year fixed-term contract finished |
| **Regretted exit** | Someone left whom the company wanted to keep | A strong engineer resigns. A poor performer resigning is non-regretted. |
| **Cohort** | A group sharing a starting point, tracked together | "Everyone hired in March 2023": how many remain after six months? |
| **Observation window** | Time that must pass before an outcome can be measured | Six-month retention for someone hired last month cannot be measured yet |
| **Censoring** | Being cut off before the observation window completes | Hired October 2025, data ends December 2025: the six-month outcome is unknown, not "retained" |
| **Cohort maturity** | Whether a whole cohort has passed its observation window | A 2025-Q3 hire cohort is not mature for a twelve-month objective |
| **Denominator** | The "out of how many" in a percentage | Five regretted exits *out of* average headcount |
| **Average headcount** | The typical number of employees over a period | Month-end headcounts averaged across twelve months |
| **Trailing twelve months (TTM)** | The twelve months ending on a given date | TTM at June 2024 covers July 2023 to June 2024 |
| **Senior hire** | A newly hired manager or leader | Which career levels qualify is a documented decision |
| **As-of date** | The date the data was frozen; nothing after it is known | 2025-12-31 for this starter pack |
| **Publication lag** | Delay between the period a statistic describes and its release | March unemployment released in May cannot explain April outcomes |
| **Frequency integrity** | Never presenting a coarse value (annual) as finer measurements (monthly) | A 2023 annual value carried forward keeps its original period and age |
| **Association vs causation** | Two things moving together does not mean one causes the other | Rising inflation and rising turnover can share a common driver |

### Objectives in plain terms

| Objective | Target | Plain meaning | Open decision |
|---|---|---|---|
| `NEW_HIRE_6M` | at least 0.86 | Of every 100 new hires, 86 or more still employed six months later | 182 days or calendar months; handling of immature cohorts |
| `SENIOR_HIRE_12M` | at least 0.90 | Of every 100 senior hires, 90 or more still employed after a year | Which career levels (including the `Sr Mgmt` label) qualify |
| `REGRETTED_TURNOVER_12M` | at most 0.075 | Regretted exits over twelve months are at most 7.5% of average headcount | Headcount convention; treatment of unknown regretted flags |
